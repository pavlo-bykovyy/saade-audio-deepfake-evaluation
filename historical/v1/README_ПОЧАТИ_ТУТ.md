# SAADE–AUA: інструкція до Jupyter-проєкту

## Призначення

Повна експериментальна реалізація двоетапного **Scenario-Adaptive Audio Deepfake Evaluation** для україномовного аудіокорпусу AUA. Усі вихідні файли AUA **лише читаються**. Нова вибірка, контрольні split, ваги моделей, метрики, графіки та архів звітів зберігаються в `/home/jovyan/work/results/SAADE_AUA_2026_v1`.

**Вихідний архів `AUA_FULL_AUDIT_20261114_202658.zip` містить звіти, а не WAV-файли**. Для виконання аудіо має існувати на сервері за адресою `/home/jovyan/work/AUA`. Ноутбук сам перевірить наявність каталогу.

## Файли проєкту

- `SAADE_AUA_Full_Pipeline.ipynb` — центральний покроковий ноутбук: 12 етапів та опціональні моделі;
- `saade_core.py` — код збору каталогу, інженерії сценаріїв, навчання, метрик і статистики;
- `requirements_SAADE.txt` — Python-залежності (PyTorch не потрібно перевстановлювати без перевірки CUDA);
- `README_ПОЧАТИ_ТУТ.md` — ця інструкція.

## Старт

1. Розпакуйте `SAADE_AUA_Project.zip` у `/audio_real_fake/` у JupyterLab (або іншу папку). **`ipynb` та `saade_core.py` мають лежати поруч**.
2. Відкрийте `SAADE_AUA_Full_Pipeline.ipynb`.
3. Перевірте `DATA_ROOT` у комірці налаштувань (типово `/home/jovyan/work/AUA`).
4. Запустіть **Kernel → Restart Kernel and Run All Cells**. Перший запуск завершиться лише валідаційною частиною: фінальний hidden test заблокований.
5. Перевірте `01_catalog_issues.csv`, `03_split_summary.csv`, `05_adaptive_weights.json`, валідаційні метрики й графіки.
6. Переконайтесь, що `06_FINAL_PROTOCOL.json` зафіксований. **Лише після цього** встановіть `RUN_FINAL_HIDDEN_TEST = True` в етапі 10 і запустіть комірку, а потім етапи 11–12.
7. Завантажте `SAADE_RESULTS.zip` з результатів і передайте його для перевірки статті.

## Склад експерименту

- E1: статичне навчання на чистому аудіо;
- E2: випадкові акустичні аугментації;
- E3: адаптивний вибір аугментацій, визначений валідаційними помилками E1.

У всіх режимах порівнянний бюджет навчання (`epochs` і `augmentation_probability`), а тестовий набір не використовується для вибору сценаріїв чи гіперпараметрів. Валідаційні скоринги — розвідувальні; остаточні висновки — лише з замороженого hidden test.

За замовчуванням використовуються три повністю реалізовані, автономні моделі: **Spectrogram CNN, Raw Wave CNN, MFCC–SVM**. **Це НЕ AASIST і НЕ RawNet2**. Дійсні AASIST, RawNet2 та WavLM підключаються шляхом зміни `cfg.models=('aasist','rawnet2','wavlm')` після встановлення їхнього вихідного коду та ваг. Оберіть новий каталог `cfg.out` при перемиканні моделей чи зміні параметрів.

## Дані

Канонічне аудіо береться лише з:

- `01_audio/own_processed` — реальне власне аудіо;
- `01_audio/external_selected` — Common Voice/FLEURS;
- `01_audio/synthetic` — DRSSU/new TTS.

`own_master` — сирий дубль оброблених записів; `05_splits` — копії, які не рахуються як незалежні спостереження.

Аудит станом на 14 листопада 2026 р. містить 12.665 год канонічного аудіо, але лише 2.045 год власних записів. **Не слід представляти 3 год як виконану квоту.**

Метадані `speaker_id`, `source_record_id`, `working_sha256`, `mode`, `source_dataset` використовуються для групових розбиттів, перевірки конфліктів та збереження походження.

## Сценарії

Три рівні: шум 20/10/0 dB SNR, реальна MP3-компресія 64/32/16 kbps, синтетична реверберація з номінальним RT60 0.2/0.5/0.9 s, фільтр верхньої частоти 7/5/3.4 kHz; 1 baseline + 4 × 3 = 13 сценаріїв на первинний аудіофрагмент.

Перетворення генеруються детерміновано. Кеш `cache_scenario_waves/` може споживати до декількох гігабайтів — це **похідні файли у папці результатів**, а не дані AUA; його можна видалити після завершення обчислень, не змінюючи підсумкових CSV.

## Показники

- EER, ROC-AUC, Balanced Accuracy, F1 і помилки real/fake;
- ASRI (пропонований показник, **не** міжнародний стандарт), середнє по 12 рівноважних умовах;
- джерельно-стратифіковані метрики, позначення одно-класових джерел;
- парний кластерний bootstrap E3–E2 за group_id;
- GEE з кластеризацією за group_id (розвідувальна модель);
- SRD, DnE, DnM, WSM і TOPSIS (допоміжне ранжування, не доказ значущості).

## Наукові обмеження

1. Джерело запису може **ідеально передбачати клас**: Common Voice/FLEURS — real, DRSSU/TTS — fake. Отже, модель може розпізнавати кодек або мікрофон, а не синтетичність. **Це критичний конфаундер**, який слід вказати у статті. Для узагальнень потрібні джерельно-збалансовані або спарені real/fake піднабори.
2. Якщо не вдалося підтвердити групування мовців, `make_splits` зупиниться. Режим `allow_weak_groups=True` допустимий для технічної апробації, **але не для наукового твердження про відсутність leakage**.
3. Наявність запису в папці не підтверджує індивідуальну згоду чи право на відкриту публікацію.
4. Регіональність тексту `script_profile` не дорівнює регіональному походженню мовця.
5. Якщо немає перевіреного генератора DRSSU, не стверджувати, що виконано `unseen-generator` експеримент. `03_generator_holdout_feasibility.csv` показує лише його можливість.
6. Для офіційного AASIST/RawNet2, які можуть використовувати іншу орієнтацію класів у pretrained checkpoints, перевірте значення виходів перед імпортом сторонніх ваг; цей проєкт за замовчуванням навчає з нуля під конвенцію `0=real, 1=fake`.
7. На штучному тестовому корпусі код пройшов усі етапи. Реальна точність на AUA невідома до запуску на сервері.
