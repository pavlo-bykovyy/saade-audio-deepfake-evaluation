# SAADE–AUA v4 — сценарно-адаптивне навчання для дисертації

## 1. Що робить реалізація

**Мета дослідження** — перевірити гіпотезу, що цілеспрямований, багаторазово оновлюваний добір акустичних спотворень забезпечує вищу стійкість детекторів синтетичного мовлення, ніж рівноймовірна випадкова аугментація, за **однакових** моделі, даних, кількості епох і кількості навчальних звернень.

Визначення режимів:

- **E1 Static:** без додавання шуму / стиснення / реверберації / фільтрації;
- **E2 Random:** аугментація з імовірністю 0,5, із рівними шансами для 4 категорій і 5 рівнів;
- **E3 Online Adaptive:** та сама ймовірність 0,5; первинні ваги категорій/рівнів обчислюються за помилками **E1 на окремій adaptation-вибірці**, а потім перераховуються за помилками **самої E3** після кожних `UPDATE_EVERY` епох. Частина випадкової аугментації збережена («uniform floor»), щоб не припинити досліджувати інші сценарії.

**Достовірна перемога E3 над E2 — невідомий результат, який треба довести або спростувати; код не гарантує позитивного ефекту.**

## 4. Перед запуском

Встановіть пакети з `requirements_v4.txt` у відповідному середовищі JupyterLab. Системний `ffmpeg` обов'язковий для MP3-сценаріїв. `ipywidgets` потрібен для інтерактивного випадаючого плеєра, але **21 звичайний HTML-аудіоплеєр** працює і без нього.

Якщо треба лише перевірити аудіовізуальну частину, початково лишіть:

```python
RUN_FULL_TRAINING=False
RUN_FAST_SMOKE=False
SOURCE_MODE='existing_AUA'
```

Для перевірки коду (`1 seed`, `1 epoch`, MFCC-SVM, тільки інженерний тест):

```python
RUN_FAST_SMOKE=True
```

Для **повного навчання** (3 seeds, 15 епох, три базові моделі):

```python
RUN_FULL_TRAINING=True
RUN_FAST_SMOKE=False
SEEDS=(42,123,777)
EPOCHS=15
UPDATE_EVERY=3
```

Це може бути тривалий обчислювальний експеримент; використовуйте сервер із GPU. **15 епох — стартова експериментальна конфігурація, а не гарантія збіжності**; перед фінальним протоколом перевірте криві втрат і зафіксуйте вибір бюджету, не підбираючи його за кінцевою validation.

## 5. Валідаційна схема, щоб не підміняти новизну

1. Оригінальні записи діляться за підтвердженими групами мовців/голосів **до** нарізання на 4-секундні вікна.
2. Із тренувальних груп відокремлюється **adaptation** для добору сценаріїв і калібрування порогів. До цієї частини не входять validation або hidden test.
3. Сегменти випадково зменшуються до співвідношення **50% REAL / 50% FAKE окремо** для train, adaptation, validation, hidden test, фіксується список відібраних/виключених записів. При справжніх matched-парах використовується відбір, який зберігає пари.
4. Всі E1/E2/E3 одержують **однакові** дані train, число проходів та random seed для початкової ініціалізації моделі. E2/E3 мають однаковий шанс аугментації 0,5. Різниця E2/E3 — лише стратегія вибору категорій/рівнів.
5. **E3 policy** оцінює помилки по категоріях × рівнях, усереднює частки помилок із балансом класів та груп, згладжує малі підмножини, оновлює ймовірності з інерцією.
6. **Validation** отримує 21 сценарій для кожного фрагмента й оцінює всі seed/моделі без змін порогів/ваг/епох. Hidden test не читається цим ноутбуком.
7. Головний ефект: `ΔASRI = ASRI(E3) - ASRI(E2)` в кожній парі `(model, seed)`; додаткові — balanced accuracy, EER, ROC-AUC, F1 та криві за рівнями спотворення.
8. Якщо незалежних synthetic voice-group у validation недостатньо, **confidence interval для узагальнення за голосами заборонено показувати як надійний**. Код виводить відповідний статус, не вигадує різноманітність голосів.

**Принципове обмеження поточного AUA:** real/fake класи повністю розведені по п'яти вихідних корпусах. Навіть 50/50 та великий набір сегментів не усувають *source–label confounding*. Це дослідження у режимі `existing_AUA` — пілот методики, не остаточне дисертаційне підтвердження.

## 6. Text → TTS → пара REAL/FAKE (окремий етап)

У `SAADE_AUA_v4_Text_to_TTS.ipynb` створюється CSV `V4_00_TTS_GENERATION_QUEUE.csv` із верифікованими шляхами реального аудіо, транскрипцією, оригінальним speaker ID та уже зафіксованим split. **Текст із поля `transcription` не слід автоматично вважати дослівно перевіреним: перед генерацією його потрібно переглянути.** Для власних записів із порожнім `transcription` черга не вигадує тексту.

Після підтвердження ліцензій і текстів вручну проставте `tts_status=APPROVED`, `tts_model_id` та `tts_voice_id` для відповідних рядків. Адаптер `synthesize_piper_reviewed(...)` використовує **вже встановлений** Piper CLI та реальний локальний `.onnx` голос. Без встановлених моделей цей етап нічого не генерує.

TTS-файли та receipts (SHA256) створюються **лише в папці результатів**, не в AUA. Режим `matched_tts` використовує `integrate_tts_pairs(...)` для відповідності реального й синтетичного аудіо одного тексту. **Один TTS-голос не може використовуватися у двох частинах split.** Для такого режиму потрібні **різні голоси для train/adaptation/validation/hidden_test**, декілька незалежних голосів у validation та hidden test, а також правильне групування оригінального мовця.

Однаковий текст усуває семантичну різницю, **але не усуває** різницю мікрофона, кімнати, шуму, компресії, людського й синтетичного каналів, мови, довжини, інтонації та студійної якості. Обидва класи потрібно приводити до порівнюваних умов; ці фактори документуються.

## 7. Чому немає «гарантованої новизни»

Сценарно-адаптивний метод може бути **гіршим** за випадковий, якщо він надмірно підлаштовується під adaptation, зосереджується на невиліковних сценаріях або корпусна специфіка створює штучну перевагу. Для дисертаційного висновку потрібні matched-TTS, адекватна кількість незалежних голосів/генераторів, 3–5 seeds та незалежні тести. Експертне слухацьке оцінювання в цій версії навмисно відсутнє.
