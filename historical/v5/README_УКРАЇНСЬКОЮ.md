# SAADE–AUA v5 FINAL · дослідницький пакет JupyterLab

## Що саме перевіряємо

Центральна гіпотеза: **сценарно-адаптивне навчання E3** підвищує стійкість детектора синтетичного українського мовлення порівняно з **випадковою аугментацією E2** за однакового бюджету навчання. **Результат не запрограмований як позитивний:** E3 може програти E2, і такі результати зберігаються без виправлення.

E1 — Static, E2 — Random (uniform), E3 — Adaptive (online reweighting). Порівнюються однакові архітектури, однакові вхідні сегменти, кількість епох, seeds, імовірність застосування аугментації 50% та ті самі 21 тестовий акустичний сценарій.

**Головна метрика:** ΔASRI = ASRI(E3) − ASRI(E2), окремо для кожної моделі й кожного seed. ASRI — усереднений за 20 категоріально-рівневими впливами показник `max(0, 2×balanced_accuracy−1)`. Початковий baseline показується окремо і не входить до ASRI. Додаткові показники: EER, ROC-AUC, F1 fake, balanced accuracy, помилки першого/другого роду. Груповий bootstrap виконується **лише якщо є ≥3 незалежні групи кожного класу**; оцінки за seeds не вважаються незалежними аудіозаписами.

## 2. Чому «сценарії» мають два етапи

**Генеративний етап:** беремо транскрипцію *справжнього* запису з Common Voice/FLEURS/власного AUA і справжнім рушієм TTS синтезуємо той самий текст. Система зберігає справжній `model_id`, `voice_id`, джерело тексту, відповідний REAL-запис, результуючий WAV і його SHA-256. Без TTS-рушія з файлами голосів генерація **не виконана**; програма не підміняє її випадковим аудіо.

**Акустичний етап:** до **кожного** REAL і FAKE застосовуємо однаковий набір із 21 сценарію: baseline + шум 20/15/10/5/0 dB; MP3 64/48/32/24/16 kbps; реверберація RT60 0,2/0,35/0,5/0,7/0,9 с; низькочастотний фільтр 7000/6000/5000/4200/3400 Hz. Шум — синтетичний гаусівський, реверберація — математична, MP3 — через `ffmpeg`. Ці сценарії не породжують нових слів: вони змінюють акустичні умови для готового запису.

## 3. Як отримати REAL–TTS пари

1. Відкрийте CSV `V5_00_TTS_GENERATION_QUEUE.csv`, перевірте текст, ліцензії, згоду/дозволи та відповідність початковому людському аудіо. Порожні чи непідтверджені транскрипції не синтезуйте.
2. Для кожного схваленого рядка поставте `tts_status=APPROVED`, `tts_model_id` та `tts_voice_id` (реальні, не вигадані).
3. У `01_Text_to_TTS.ipynb` внесіть у `PIPER_MODELS_BY_VOICE` справжні шляхи до локальних україномовних `.onnx` з конфігураціями `.onnx.json`. Установіть `GENERATE_REVIEWED_AUDIO=True` **тільки після цього**. Потрібна доступна команда `piper`.
4. Успішний запуск створить `V5_00_PIPER_GENERATION_RECEIPTS.csv` і WAV у `paired_tts_generated/`. Код перевіряє SHA голосових ONNX, відхиляє підміну одного голосу кількома псевдонімами та не дозволяє використовувати той самий голос у різних split.
5. У `02_Full_Dissertation_Experiment.ipynb` перемкніть `DATA_MODE='matched_tts'` і запустіть **новий** експеримент у каталозі `SAADE_AUA_2026_v5_FINAL`. Якщо немає незалежних груп для adaptation/validation/hidden, строгий запуск зупиниться; їх не можна «створювати» перейменуванням файлів.

**Як формується adaptation:** початкова TTS-черга має train / validation / hidden_test. Після генерації алгоритм **вилучає з train** цілі незалежні компоненти `(людський мовець ↔ текстова пара ↔ TTS-голос)` в adaptation; тому для train потрібно передбачити **багато незалежних голосів**, а не один. Для обґрунтованих групових висновків у validation і hidden_test — щонайменше три реальні та три синтетичні групи в кожній; для адаптації — аналогічно. Якщо модель синтезу використовується з одним голосом, один файл під різними назвами не утворює кілька голосів.

Однаковий текст **не контролює повністю мікрофон, шум, компресію, студійність, канал, генератор чи тривалість**. Це окрема умова якісного експерименту: однакове ресемплювання в 16 kHz mono є необхідним, але не достатнім контролем конфаундингу.

## 4. Пілот — коли ще немає реального TTS

У головному ноутбуці встановлено `DATA_MODE='pilot_existing'` та **`RUN_TRAINING=True`** (3 seeds × 15 епох). Пілот використовує вже існуюче AUA та тестує інженерну працездатність; **його метрики не можна видавати за незалежний доказ дисертаційної гіпотези** через повне змішування корпусів і real/fake в джерелах.

Моделі за замовчуванням: `spectrogram_cnn`, `raw_wave_cnn`, `mfcc_svm`. Опційні `aasist`, `rawnet2`, `wavlm` підтримуються кодом, **але потребують окремих справжніх репозиторіїв, чекпойнтів або бібліотек**; вони не запускаються автоматично і не видаються за вже перевірені. Не називайте `raw_wave_cnn` моделлю RawNet2.

Аудіоплеєри, таблиці 21 сценарію й статичні графіки можна перевірити до тренування, а потім `03_Results_Audio_Viewer.ipynb` прочитає вже готові результати без повторного навчання. Переглядач типово відкриває `...v5_PILOT`; для matched-режиму змініть `OUT` на `...v5_FINAL` в першій комірці.

## 5. Статистика та інтерпретація

Динамічний E3 використовує **тільки adaptation** для повторного оновлення категорійних і рівневих ваг за помилками. Всі 21 сценарії на validation тестуються з фіксованими, однаковими параметрами, але validation **не бере участі** у навчанні/адаптації. ASRI та ΔASRI обчислюються **окремо за seed**; графіки за сценаріями також будуються окремо за seed, щоб не вважати повторні оцінки новими аудіозразками. Стратифікований bootstrap відбирає **групи голосів** з обох класів; при їх нестачі повертається `INSUFFICIENT_INDEPENDENT_VOICES`, а не вигаданий довірчий інтервал. GEE має дослідницький, а не підтверджувальний статус.

Позитивний ΔASRI — необхідна, але не достатня умова для висновку про користь SAADE. Потрібні повторні seeds, незалежні голоси/генератори, зіставленість акустичних умов і відтворюване незалежне тестування. Науковий результат може виявитися негативним.
