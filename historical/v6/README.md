# SAADE–AUA v6 — REAL–TTS matched-підкорпус і сценарно-адаптивний експеримент

## Що містить пакет

**Один самодостатній Jupyter Notebook:** `SAADE_AUA_ALL_IN_ONE_v6_MATCHED_TTS.ipynb`. П'ять модулів попереднього SAADE v5.1 **вбудовані** у файл. Не потрібно шукати чи завантажувати `saade_core.py` або кілька незалежних ноутбуків.

Ноутбук створює **реальні**, а не імітовані синтетичні аудіозаписи з точних текстів наявних записів Common Voice в AUA, використовуючи Piper TTS. Далі створює REAL–FAKE пари 50/50, перевіряє походження, зберігає незалежність відомих мовців і TTS-голосів, оцінює E1 Static / E2 Random / E3 Online Adaptive за 21 акустичним сценарієм і виводить аудіоплеєри/графіки.

## Як запустити

1. Завантажте **лише `.ipynb`** у JupyterLab, відкрийте його та оберіть `Kernel → Restart Kernel and Run All Cells`.
2. За замовчуванням `RUN_TTS_GENERATION=True`, `AUTO_DOWNLOAD_PIPER_VOICES=True`, `AUTO_INSTALL_TTS_PACKAGES=True`: код перевірить залежності, за потреби встановить **лише** `piper-tts` і `huggingface_hub`, отримає реальні ONNX із Hugging Face та синтезує WAV. Він не перевстановлює PyTorch/CUDA.
3. Якщо сервер без Інтернету, встановіть `AUTO_DOWNLOAD_PIPER_VOICES=False` й задайте `LOCAL_PIPER_VOICES` із реальними шляхами до `.onnx` та відповідних `.onnx.json` у доступній директорії. Власну TTS-модель **не можна імітувати**: без неї немає matched-аудіо.
4. Результат автоматично виведе таблиці 50/50, усі 21 сценарій, прогноз E1/E2/E3, зміну ваг E3, ASRI та ZIP для перегляду.

Дані відбираються **з повного авторитетного каталогу AUA**, а не з уже скороченої вибірки попереднього пілоту. Обмеження `TTS_MAX_UTTERANCES=600` означає **до** 600 первинних REAL та до 600 TTS-аудіо, якщо вистачить підтверджених текстів та якщо файли пройдуть QC. Кожен реальний мовець і текст допускається лише один раз. Це **не гарантія**, що після синтезу залишиться рівно 1200 сигналів: усі відхилення записуються у `V6_TTS_GENERATION_STATUS.csv`.

За наявними метаданими підтверджені записи Common Voice є основою першого matched-підкорпусу; FLEURS поки не використовується через невстановлені індивідуальні ID мовців, власні аудіозаписи — через пропуски транскрипцій.

## Які голоси використовуються

У репозиторії `rhasspy/piper-voices` (https://huggingface.co/rhasspy/piper-voices/tree/main/uk/uk_UA) опубліковано українські підкаталоги: `lada`, `mykyta`, `oleksa`, `tetiana`, `ukrainian_tts`. **Вони не є п'ятьма незалежними генераторами**. Код використовує 3 голоси для train, 1 для validation та 1 для hidden; одну тренувальну голосову компоненту переносить в adaptation. Зберігає реальний ONNX SHA, ревізію репозиторію та посилання на модель. Перед поширенням згенерованих WAV перевірте ліцензії та модельні картки кожного голосу.

**Методологічне обмеження:** цього недостатньо для ≥3 незалежних FAKE-голосів **одночасно** в adaptation, validation і hidden, тому строгий кластерний bootstrap поверне `INSUFFICIENT_INDEPENDENT_VOICES`; це не збій. Для дисертаційних висновків про узагальнення на невідомі генератори треба додати інші незалежні голоси/генератори, виконати новий group-disjoint протокол та лише тоді остаточний hidden test.

## Науковий статус і обмеження

Головна гіпотеза: `ΔASRI = ASRI(E3) − ASRI(E2) > 0` на незалежних тестових голосах/генераторах. **Код не гарантує позитивного результату.** Реальне та синтетичне мовлення має той самий текст, але ще відрізняється походженням, каналом запису й генератором. Пілот Piper не усуває конфаундинг реальний корпус vs TTS. Синтетичний аудіосигнал не має доказів, що кожне слово промовлено безпомилково; до фінального випуску потрібен контроль вимови/ASR або аудиторська перевірка.

### Що перевірено перед передачею

- `nbformat` і синтаксис усіх кодових комірок;
- фактичні 600 кандидатів на основі збереженого каталогу `01_catalog_all.csv` попереднього запуску, із відсутністю повторних мовець/text груп між train/validation/hidden;
- інтеграція 42 **тимчасових контрольних** пар, адаптаційний fold і баланс 50/50, без претензій, що це були реально згенеровані голоси;
- виклик синтезатора, перевірка SHA-256, збереження receipts та ідемпотентне повторне використання файлів — на заглушці звукового рушія (тільки програмний тест).

**Не виконано в середовищі створення:** завантаження й фактичний запуск 5 українських голосових моделей Piper та повне навчання на віддаленому AUA, оскільки їхні файли є лише на вашому сервері. Після запуску перевірте статуси синтезу та підсумки, а не припускайте успішність за наявністю CSV.
