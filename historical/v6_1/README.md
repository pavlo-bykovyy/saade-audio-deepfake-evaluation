# SAADE–AUA v6.1 — виправлення завантаження моделей Piper

Цей ноутбук є повною самодостатньою версією v6 з виправленою коміркою «4. Реальні українські голоси Piper».

## Що було не так

У серверному середовищі `huggingface_hub` використовував несумісний декодер Brotli і падав із `TypeError: process() takes no keyword arguments` під час завантаження файлів `.onnx.json`. Модель `.onnx` завантажувалася нормально.

## Що змінено

- Маленькі JSON-конфігурації та картки моделей завантажуються через Python `urllib.request` із заголовком `Accept-Encoding: identity`, без httpx2/Brotli.
- Уже наявні `.onnx` моделі (понад 1 МБ) повторно не завантажуються; контрольні суми зберігаються у реєстрі походження.
- Валідація структури Piper JSON, перевірка повноти файлів та атомарний запис.
- Режим `matched_tts`, балансування, E1/E2/E3, сценарії, графіки, hidden-test guard **не змінено**.
- Шляхи: AUA `/home/jovyan/work/audio_real_fake/AUA` тільки читання, результати `/home/jovyan/work/audio_real_fake/results`. Папка `Melnyk_dus` не змінюється.

## Як відновити запуск

1. Відкрийте `SAADE_AUA_ALL_IN_ONE_v6_1_TTS_DOWNLOAD_FIXED.ipynb` у JupyterLab.
2. Перезапустіть kernel і запустіть комірки від початку, або продовжіть у поточному kernel із комірки **«4. Реальні українські голоси Piper»**. Попередня черга `V6_TTS_QUEUE.csv` буде повторно використана.
3. Зверніть увагу на рядки `[lada] OK: ONNX + JSON`, тощо. Після цього йде етап **«5. Text → TTS»**.
4. Якщо з'явиться помилка інша, надішліть точний traceback; не змінюйте версії PyTorch/CUDA навмання.

## Перевірка

Структура й синтаксис ноутбука та автономні тести завантажувача пройшли. Реальний мережевий доступ до Hugging Face й генерація Piper на вашому сервері тут не перевірялися.
